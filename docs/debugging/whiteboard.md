# Debugging the whiteboard: its session-log events

The whiteboard's rows of the session-log table in [DEBUGGING.md](../DEBUGGING.md), one event family or action per
line, so that two changes adding events to the board touch different lines. The logs, how to pull them and how a line
is added are in [DEBUGGING.md](../DEBUGGING.md); this file only says what each whiteboard event holds (key fields).

**Adding a line here**: a new event or action is a new bullet under its area (or a new area), and a new field is added
to that event's own bullet; never join two events on one line.

## Between a board and its chat (stories 1206–1208, 1223–1226, bead context-grabber-dbku; spec 2026-10-25-native-chat-design.md, *Between a board and its chat*)

- `jump`, one per hop between a board and its thread: from (thread_board — a thread's *Board* —, picture — *Jump to board* on a picture —, board_panel, board_note, list_bubble — the boards list's chat bubble), to: board / thread, board, thread, how: slid_in (pushed over where he was; *Back* returns) / went_back (the target was the screen he jumped from, so one step back) / brought_forward (a board open elsewhere, opened the link's way), and through_list: true only for brought_forward
- `whiteboard` action: aside_for_chat with board and strokes — the board saved and its mic stopped as its thread slides in over it; back_from_chat with board — the board on screen again; closed_under_chat with board — the whiteboard taken down with the thread, or anything pushed from it, still over the board, so the board closes as it would on leaving

## The Board Lab (story 1501, spec 2026-11-22-board-lab-design.md)

- `board_lab` action: session with name (the recorded session asked for), status (the fake Cockpit's HTTP answer, 0 when the request failed) and error (the request's error, empty when it was sent): whether the fake Cockpit accepted the lab's request to play a recorded session on the first board message's thread, once per launch that asks for one

## The PaperKit board

- `paperkit_board` with `action` set to `opened` as the scratch page is about to appear. `inks` lists the picker’s configured PencilKit ink identifiers, `shapes` and `features` count the enabled shapes and features, and `tool` holds the page’s drawing ink identifier or `other` for a non-inking tool.
- `paperkit_board` with `action` set to `picker_check` a second after the scratch page appears (story 1222, bead context-grabber-wvpv): `picker_visible` (PencilKit's tool picker is showing), `first_responder` (the page is PencilKit's first responder, without which the picker never shows), `accessory` (the picker's **+** is set), `in_sheet` (the page sits in a sheet, not full screen) and `presentation` (the presentation style of the screen the page is on, as UIKit's modal presentation style number, `none` when it was not presented), `size_class` (`compact` inside a form sheet), `touch_mode` (`drawing` when a finger draws, `selection` when it only selects) and `auto_draws`. `picker_visible: false` with `first_responder: false` is the 2026-11-22 "Nothing there?".
- `paperkit_board` with `action` set to `closed` as the scratch page is about to disappear. `elements` counts the markup elements on the page at that point.

## Whiteboard playback (stories 954–958, bead context-grabber-3tdv)

- `whiteboard` action:
  - playback_start with board, strokes, timed (strokes drawn over time: their points have time offsets), shared (strokes that share one moment and appear together), real_s (first stroke's start to the last one's end, as drawn), plays_s (the playback's length) and ms (building the timeline): Play tapped. Timed far below strokes says a board's timestamps didn't survive. Also (#1169) rules (none, grid, ruled), pages, ghost (the faint whole board drawn) and ghost_ms (its cost), opened_page (the page showing when Play was tapped) and first_page (the first stroke's page): opened_page past first_page is a playback that starts off the screen
  - playback_offscreen with board, where (above, below, on_screen), page (the stroke's), visible_page, stroke and at_s: story 1111's label appearing, changing or going
  - playback_go with board, stroke and page: the label tapped, the board moved to the stroke
  - playback_seek with board, how (tap, scrub, back, forward, voiceover), from_s, to_s and stroke (a tap's or VoiceOver's stroke, its place in the drawing)
  - playback_tap with board, hit: false and showing: a tap in playback that found no stroke near
  - playback_speed with board and speed
  - playback_end with board, watched_s, reached_end, seeks, at_s, frames (new drawings set), slowest_draw_ms (the slowest of them, a big board's cost) and offscreen_shown (how often story 1111's label showed): Done, or the board closing

- `whiteboard` action **paper_drop** for moves of ink with no strokes added or removed, outside Undo and Redo (stories 969, 973–975, 979, 1172, 1177, 1178). `board`, `strokes`, `at` (landing box), `from` (starting box), `selected` (the current selection count), and `pickup`:
  - `selected` means every moved stroke was selected at the time of the move or held at the start of the touch. `dragged` means the strokes moved together during a touch sequence without a selection holding all of them.
  - `not_rigid` means the strokes moved by different amounts. `split` means both owners' ink moved and the owners-apart rule took over. Both log `room: false`. A move outside a touch sequence that qualifies as neither `selected` nor `split` is skipped.
  - A drop with no room to open logs `room: false`. A planned push includes `cut`, `dy` and `moved`. It also logs `waited_ms` (the wait for the touch sequence to end, capped at 3 s) and `now_is_drop` (whether the stroke frames still match the drop within tolerance). `room: false` with `stale: true` means the frames or stroke order changed and the plan was skipped. The planned `cut`, `dy` and `moved` are still present in that case.
  - A `dragged` drop that moved only part of a group (story 1193) also logs `carried` (how many of the group's other strokes it brought along by the same offset) and `carried_groups` (their group names). `at` and `from` then include those strokes. With nothing to push, it still carries them in one Undo named *Move* and logs `room: false` with no `cut`, `dy` or `pushed_now`.
  - An attempted push logs `room: true`, `took_back` (whether a PaperKit Undo step was taken), `undid_drag` (whether the resulting frames match the pre-drag board), and `on_live` (whether the push uses the strokes from after that Undo). If applying the push fails it logs `failed: true`. Otherwise it logs `pages`, `undo_name` (the current Undo step), `pushed` (the number of strokes the push targeted), and `pushed_now` (how many of those strokes are at the intended vertical offset).

- `whiteboard` action **paper_resize_as_move**, a stretch PaperKit made of a drag begun on a handle inside a selection, made a move after the lift (story 1201). `before` (the box at touch-down), `stretched` (PaperKit's), `travel` (the finger's, board points), `handle`, `strokes`, `waited_ms` (how long after PaperKit's stretch the finger lifted; the word shows stretched until then and a beat after), `took_back` and `undid_stretch` (PaperKit's step taken back, and the strokes back where they were; when not, the stretch is left and nothing else is said), then `after`, `room`, `moved` and, with room made, `cut` and `dy`; `failed` when the move couldn't be put on.
- `whiteboard` action **paper_drop_after**, a second after applying a push (story 1172). `board`, `pushed`, `pushed_now`, `in_touch` (whether the touch sequence is still active) and `undo_name`. If `pushed_now` is below `pushed`, some strokes are no longer at the intended offset. Check for an intervening edit or Undo when diagnosing a lost push.
- `whiteboard` action **paper_apart**, after a `paper_ink` with `apart: split` (stories 1145–1147): board, back (strokes put back), whose (theirs or mine), moved, in_touch, took_back (PaperKit's step was taken back), undid_move (the take-back restored the board as it was before the move), how (**took_back**: the restored board with the moving owner's strokes put on it; **moved_back**: the take-back redone and the put-back strokes moved back by their offsets), back_in_place (put-back strokes now where they were, at their size before the move), can_undo, undo_name (Move when it worked).

## What goes to the Cockpit for its board debug page (story 1112, bead context-grabber-7zmj)

Not session-log lines: fields on what the board sends, so the Cockpit's GET /debug/board can show what only the iPad knows. Each is kept by the Cockpit as sent (the events land in `whiteboard-events/<board>.jsonl`, a turn's on its `via: "turn"` row).

- `build` (`<sha> <branch>`) on every board picture's chat message (the hand-off and *Send to Larry*) and on every `POST /whiteboard/events`; both also carry `app_build` and `app_sha`, as every post to the Cockpit does (story 1134)
- `board_title` (the board's name when the picture was taken) on every board picture's chat message and its `POST /whiteboard/strokes`, not only the first that starts the chat; a Cockpit since a248425 retitles an app-named chat *Board: <name>* when it changes and shows it on the debug page (story 1101, bead context-grabber-8rei)
- a `post` event among each hand-off's events: t (unix ms the message left), build, from (button, responder, retry, …), render_ms, encode_ms, strokes_ms, upload_ms and bytes; a *Retry* carries its own
- a `mic` event for each spoken stretch taken for a turn: t (mic on, unix ms), words_t, off_t (absent while the mic stayed open), text_t, sent_t, to_words_ms, on_to_off_ms, off_to_text_ms, text_to_sent_ms and chars (never the words); it rides with the next picture handed to Larry, or the next events batch

## To text and shape snap (stories 920–925, spec 2026-11-16-whiteboard-to-text-and-snap-design.md)

- `whiteboard` with `action`:
  - **to_text**, a tap on *To text*: `board`, `strokes`, `png_bytes`, `crop`
  - **to_text_done**, the answer: `board`, `ms`, and `outcome`: **text** (with `text_id`, `chars`, `lines`, `glyphs`), **no_writing**, **too_long**, **ink_gone** (the lassoed ink went while it was read), **no_letters** (the words made no strokes)
  - **to_text_failed**: `board`, `ms`, `reason`, `status` (the HTTP status, absent on a network error), with an `error` (where: whiteboard_to_text, `message`, `status`, `board`) beside it
    - an `error` with message *no picture* when the ink's picture couldn't be drawn
  - **paper_select_hook**, `GRABBER_WHITEBOARD_AFTER_INK=select`: `board`, `selected`
  - **shape_snap**, a held stroke swapped for its clean shape: `board`, `kind` (line, rectangle, ellipse), `err`, `points`, `clean_points`, `width`
  - **shape_snap_none**, a held stroke that is no shape and stays ink: `board`, `points`
